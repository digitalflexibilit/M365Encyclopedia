# Digest 2026-11-16

## Copilot
- **Maker guidelines for Copilot Studio** (Power Platform admin center, Preview): Admins can show Copilot Studio makers a short message with an optional link and contact email in an agent's Review pane, to point them to internal guidance and request processes. Set per environment or environment group, Managed Environments only. [More info](https://learn.microsoft.com/en-us/power-platform/admin/maker-guidelines)
- **Skills in Copilot Studio setting** (Power Platform admin center, GA): Admins choose which types of skills Copilot Studio agents can reference, per environment or environment group. The setting replaces the Copilot Studio virtual connectors in classic data policies. [More info](https://learn.microsoft.com/en-us/power-platform/admin/skills-copilot-studio-rule)
- **Environment routing for Copilot Managed Runtime** (Power Platform admin center, GA): Routing for Copilot Managed Runtime is on in all tenants and cannot be turned off. Tenants without routing rules get an Everyone rule and personal managed environments for makers; tenants with existing rules block makers outside the rule security groups from building these apps until an Everyone rule is added. [More info](https://learn.microsoft.com/en-us/power-platform/admin/default-environment-routing-copilot-managed-runtime)

## Word
- **Heading checks in Accessibility Assistant** (Word, Preview): Accessibility Assistant in Word for Windows now flags fake headings made with bold or larger text, long sections without a heading and headings split across paragraphs. Available to Microsoft 365 Insiders on Version 2610 (Build 20620.20002) or later. [More info](https://techcommunity.microsoft.com/blog/microsoft365insiderblog/improved-detection-for-improper-or-missing-headings-in-word/4506225)

## Power Apps
- **Display density in model-driven apps** (Power Apps, Preview): Users can choose Comfortable, Cozy or Compact spacing in Personal settings, and admins and makers can set environment and app defaults. Requires the header and navigation refresh (wave 2). [More info](https://learn.microsoft.com/en-us/power-apps/user/appearance-settings)

## Power Automate
- **Power Automate plugin for GitHub Copilot CLI and Claude Code** (Power Automate, GA): Makers can create, edit, run, debug and manage cloud flows from a terminal coding agent in natural language, and list and run desktop flows. The plugin uses the signed-in user's permissions and data policies. [More info](https://learn.microsoft.com/en-us/power-automate/power-automate-plugin-external-tools)

## Power Pages
- **Client API** (Power Pages, GA): The $pages JavaScript API lets developers work with forms, lists, authentication, languages and Dataverse records and files, call cloud flows, and send messages or events to Copilot Studio agents. [More info](https://learn.microsoft.com/en-us/power-pages/configure/client-api/)
- **Transfer site ownership** (Power Pages, GA): Admins can make another member user the primary owner of a site from the Power Platform admin center. The previous owner can lose access, and transfers are logged in Microsoft Purview. [More info](https://learn.microsoft.com/en-us/power-pages/admin/transfer-ownership)

## Dataverse
- **Filter-based security** (Dataverse, Preview): Admins can grant row-level access based on record values, such as territory, through FetchXML filters assigned in security roles. A new Filtered table ownership type uses only these filters. [More info](https://learn.microsoft.com/en-us/power-platform/admin/filter-based-security)
- **Dataverse governance policies** (Dataverse, GA): Admins review Dataverse storage in the Power Platform admin center and choose bulk deletion or long-term retention for data, with cleanup recommendations from the storage advisor (preview). Retention policies need a Managed Environment. [More info](https://learn.microsoft.com/en-us/power-platform/admin/dataverse-governance-policies)
